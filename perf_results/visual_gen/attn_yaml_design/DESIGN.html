Visual-Gen Attention YAML — Design Refinement

Scope: user-facing CLI/YAML for quantized + sparse attention algorithms in tensorrt_llm/_torch/visual_gen. Grounded in PR #12947 (SkipSoftmax) and existing SageAttention hooks already in the backend.

TL;DR

Adopt PR #12947's pattern verbatim for the new Sage knobs: add a sibling quant_attention_config sub-block under attention, with a Pydantic discriminated Union on the algorithm field (mirroring the existing sparse_attention_config). Keep the top-level quant_config: reserved for linear-layer weight / activation quant (FP8 / NVFP4) — do not overload that name inside attention.

1. Current state in main

Today the user-facing AttentionConfig (tensorrt_llm/_torch/visual_gen/config.py) is a single literal: 

class AttentionConfig(StrictBaseModel):
    backend: Literal["VANILLA", "TRTLLM", "FA4", "MXFP8_CUDNN"] = "VANILLA"

There is no surface for SageAttention or sparse attention. Backend names map to:

NameModuleNotes
VANILLAattention_backend/vanilla.pyPyTorch SDPA fallback
TRTLLMattention_backend/trtllm.pyC++ kernel, hosts Sage + SkipSoftmax knobs
FA4attention_backend/flash_attn4.pyCuTe-DSL Flash-Attention-4 (do not rename to CUTEDSL)
MXFP8_CUDNNattention_backend/mxfp8_cudnn.pycuDNN SDPA-MXFP8, sm100+ self-attn

2. PR #12947 — the pattern already merged

precedent The SkipSoftmax PR establishes a discriminated-union sub-config under attention: 

attention:
  backend: TRTLLM
  sparse_attention_config:           # discriminated Union via `algorithm`
    algorithm: skip_softmax
    threshold_scale_factor: 5000.0
    target_sparsity: 0.7
    formula: { a: 0.0003, b: 7.5 }   # log-space form: { log_a, b }
    layer_overrides:
      "transformer_blocks.0*": 0     # 0 disables sparsity on matching layers
  sparse_config_path: /opt/ckpt/sparse.yaml   # optional path-based override

Backend coupling is enforced by validation in modules/attention.py, not by hierarchy: 

if isinstance(ss_cfg, SkipSoftmaxConfig) and backend_name == "TRTLLM":
    ...

Cross-attention falls back to VANILLA because the TRT-LLM C++ kernel requires fused QKV.

3. Existing Sage hooks in the backend

tensorrt_llm/_torch/visual_gen/attention_backend/trtllm.py and _torch/attention_backend/interface.py already accept these per-layer parameters — the YAML just doesn't expose them yet:

sage_attn_num_elts_per_blk_qintPer-block dynamic-quant granularity for Q (0 = disabled)
sage_attn_num_elts_per_blk_kintPer-block granularity for K

4. Refined YAML design

attention:
  backend: VANILLA | TRTLLM | FA4 | MXFP8_CUDNN

  # (A) Quant-attention: changes numerics of QK^T / PV via per-block quant.
  # Orthogonal to top-level `quant_config:` (which handles LINEAR layers).
  quant_attention_config:           # discriminated Union via `algorithm`
    algorithm: sage                 # sage | sage2 | fp4_attn (future) ...
    q_block_size: 64                # was your `q_ele`
    k_block_size: 64
    v_block_size: 256
    qk_int8: true                   # int8 QK^T path; false => fp8
    layer_overrides:                # fnmatch pattern -> enable/disable
      "*cross_attn*": false

  # (B) Sparse-attention (merged in PR #12947, unchanged).
  sparse_attention_config:
    algorithm: skip_softmax
    threshold_scale_factor: 5000.0
    target_sparsity: 0.7
    formula: { a: 0.0003, b: 7.5 }
    layer_overrides: { "transformer_blocks.0*": 0 }
  sparse_config_path: null
  quant_attention_config_path: null  # reserved for future ModelOpt-emitted sage.yaml

5. Deltas vs your raw draft

Your draftRefinedWhy
attention.quant_config: attention.quant_attention_config: Top-level quant_config: already exists for linear-layer weight/activation quant (FP8 / NVFP4 / FP8_BLOCK_SCALES). Reusing the same key inside attention makes log lines and code search ambiguous. Distinct key, distinct scope.
algo: SAGE algorithm: sage (Pydantic discriminator) Matches PR #12947's algorithm: skip_softmax. Lowercase + algorithm keeps both configs visually parallel; Annotated[Union[...], discriminator="algorithm"] validates them identically.
q_ele: 1, k_ele: 4, v_ele: 1 q_block_size, k_block_size, v_block_size The C++ kernel parameter is literally sage_attn_num_elts_per_blk_q — "elements per block" = block size. q_ele=1 reads as "1 element per block" (useless) or "the 1st element" — nobody can tell. Be explicit.
int8: True qk_int8: true The flag only controls the QKT int8 path (V keeps its own dtype). Plain int8 reads as "everything int8." Match the C++ name sage_attn_qk_int8.
top-level sparse_config: attention.sparse_attention_config: PR #12947 already nested it under attention — it's a property of attention, validated jointly with backend.
backend: CUTEDSL backend: FA4 The CuTe-DSL attention is already exposed as FA4 (attention_backend/flash_attn4.py). Use the name that exists.
(no layer overrides for Sage) layer_overrides: {pattern: bool} SkipSoftmax has them; symmetric ergonomics. In WAN cross-attn is only 0.45 % of runtime — disabling Sage there is a common operation.

Don't hard-code backend coupling in the hierarchy

Sage and SkipSoftmax are TRTLLM-only today. Resist nesting them under the backend (e.g. attention.trtllm.sage:) — that breaks when you flip backends to experiment. Instead, add a single @model_validator(mode="after") on AttentionConfig that raises if either sub-config is set with backend != "TRTLLM". This is what PR #12947 does.

6. Pydantic skeleton

class SageConfig(StrictBaseModel):
    algorithm: Literal["sage"] = "sage"
    q_block_size: int = PydanticField(64, gt=0)
    k_block_size: int = PydanticField(64, gt=0)
    v_block_size: int = PydanticField(256, gt=0)
    qk_int8: bool = True
    layer_overrides: Optional[Dict[str, bool]] = None   # pattern -> enable/disable


QuantAttentionConfig = Annotated[
    Union[SageConfig],                    # SageV2Config, FP4AttnConfig, ... later
    PydanticField(discriminator="algorithm"),
]


class AttentionConfig(StrictBaseModel):
    backend: Literal["VANILLA", "TRTLLM", "FA4", "MXFP8_CUDNN"] = "VANILLA"

    quant_attention_config:        Optional[QuantAttentionConfig]  = None
    sparse_attention_config:       Optional[SparseAttentionConfig] = None   # PR #12947
    sparse_config_path:            Optional[str] = None
    quant_attention_config_path:   Optional[str] = None

    @model_validator(mode="after")
    def _validate_backend_coupling(self):
        if (self.quant_attention_config or self.sparse_attention_config) \
                and self.backend != "TRTLLM":
            raise ValueError(
                "quant/sparse attention algos currently require backend=TRTLLM"
            )
        return self

7. What sparse_config_path is for

It's the override pointer at a ModelOpt-emitted calibration YAML. Three things to know:

7.1 File format expected on disk

load_sparse_config_from_yaml (in tensorrt_llm/_torch/visual_gen/config.py) expects ModelOpt's diffusion-sparsity calibration format — not a hand-rolled schema: 

config_groups:
  group_0:
    sparse_algo: softmax_skip
    targets: [WanAttention]
    threshold_scale_factor:
      formula: log_a + b * target_sparsity
      prefill: {log_a: -14.14, b: 36.64}
    disabled_layers: [blocks.0.attn1, blocks.0.attn2, blocks.39.attn2]

Source: test_load_modelopt_yaml fixture in PR #12947.

7.2 Resolution priority (4 possible sources)

When the pipeline loads, there are four ways a SkipSoftmax config can show up. They are resolved in this order:

#SourceRoleWins over
1attention.sparse_config_path (this field)Base: formula + disabled-layersauto-detected YAML, embedded config.json
2Auto-detected sparse.yaml / sparse.<component>.yaml in checkpoint dirBaseembedded config.json
3sparse_attention_config embedded in config.jsonBase—
4attention.sparse_attention_config: in user YAMLOverrides the base via model_copy(update=...)all of the above (per-field merge)

In one line: file-based sources provide the calibration formula + disabled layers; the user's YAML provides the operating point (target_sparsity / threshold_scale_factor / extra layer_overrides) and wins on conflicts via per-field merge. 

yaml_path = attention_cfg.sparse_config_path
if yaml_path is not None: yaml_sparse = load_sparse_config_from_yaml(yaml_path)
if yaml_sparse is None: yaml_sparse = auto_detect_sparse_yaml(...)
if yaml_sparse is None: yaml_sparse = auto_detect_sparse_attention_config(ckpt_dict)
if yaml_sparse is not None:
    user_cfg = attention_cfg.sparse_attention_config
    if user_cfg is not None and isinstance(user_cfg, SkipSoftmaxConfig):
        merged = yaml_sparse.model_copy(update={...user_cfg fields...})

7.3 When would you actually set it?

  • The calibration sparse.yaml ModelOpt emitted lives outside the checkpoint dir (e.g. shared calibration cache).
  • The filename doesn't match the strict glob (sparse.yaml / sparse.*.yaml) — e.g. you renamed it my_calibration_v2.yaml.
  • You want a deterministic CI run that pins the calibration explicitly and doesn't depend on dir-scan ordering.
  • You're A/B-comparing two calibrations against the same checkpoint.

Otherwise, leave it null and let auto-detect do its job.

7.4 The analogue for Sage

Sage has no calibration-emitted YAML convention today, but it likely will (per-layer block sizes are a calibration output). Reserve attention.quant_attention_config_path: Optional[str] now so the future auto-detect path doesn't force a YAML schema change.

8. Open questions

  1. Can Sage + SkipSoftmax run in the same model? The YAML allows it, but the C++ kernel needs to support both simultaneously. Need to confirm with the kernel owner (or test on a small model).
  2. Per-layer block sizes for Sage? Today layer_overrides is Dict[str, bool] (enable/disable). If calibration produces per-layer granularity, we'd lift it to Dict[str, SageLayerOverride] with optional block-size overrides. Plumb the schema now if we expect that within a release.
  3. FA4 / cuTe attention support for these algorithms? If FA4 grows a Sage/SkipSoftmax path, the _validate_backend_coupling validator becomes a per-algorithm allow-list: SageConfig.supported_backends: ClassVar = ("TRTLLM",).
  4. Default block sizes. SageAttention paper defaults are q=k=64, v=256; confirm this is the sweet spot on B200 for WAN before baking them in.
